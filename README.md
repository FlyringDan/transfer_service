# Transfer Service
Cервис для переводов денег между пользователями

## Cтруктура проекта
```
transfer_service/
├── transfer_service.cs        # основной файл, с API
├── db.cs                      # модели User и Transfer для базы данных
├── transfer_service.csproj    # описание проекта и зависимостей
├── appsettings.json           # конфиги
├── appsettings.Development.json
├── Dockerfile                 # Docker
└── docker-compose.yml         # Docker-compose
```


## Схема базы данных
**User**
| Поле | Тип | Описание |
|---|---|---|
| Id | int | id пользователя |
| giud | string? | guid пользователя |
| balance | decimal | баланс пользователя |

**Transfer**
| Поле | Тип | Описание |
|---|---|---|
| Id | int | id перевода |
| FromUserId | string | giud отправителя |
| ToUserId | string | giud получателя |
| Amount | decimal | сумма перевода |
| IdempotencyKey | string | ключ идемпотентности |

### Ограничения
**User**
`balance` - всегда положителен

**Transfer**
`Amount` - всегда положительна
`IdempotencyKey` - уникален

## API
| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/addUser` | создать пользователя |
| GET | `/api/users` | получить список всех пользователей |
| POST | `/api/transfers` | выполнить перевод между пользователями |
| GET | `/api/transfers/{id}` | получить информацию о переводе по id |
| GET | `/api/users/{id}/balance` | получить баланс пользователя по id |

Пример запроса на перевод:
```json
{
  "fromUserId": "guid",
  "toUserId": "guid",
  "amount": 100.50,
  "idempotencyKey": "client-generated-key"
}
```

## Описание конкурентного контроля
Создание записи о переводе средств в базе данных происходит один раз с помощью функции `SaveChangesAsync()`. 


## Описание идемпотентности
`idempotencyKey` создаётся на стороне клиента и передаётся в POST-запросе. Это нужно для безопасного перевода, при остановке сервиса.

Логика на сервере:
1. При получении запроса сервис ищет перевод с таким же `IdempotencyKey` в базе.
2. Если запись найдена — возвращается результат уже выполненной операции, новый перевод не создаётся.
3. Если записи нет — выполняется перевод, и новая запись сохраняется вместе с ключом.


## Обработка ошибок
Эндпоинты возвращают:
- `400 Bad Request` — некорректные входные данные (отрицательная сумма, перевод самому себе, отсутствующие обязательные поля, недостаточно средств);
- `404 Not Found` — отправитель, получатель или перевод не найдены;
- `200 OK` — успешное выполнение.

## Environment variables
Подключение к PostgreSQL: `Host=postgres;Port=5432;Database=transfer_service;Username=postgres;Password=12345`


## Docker
В репозитории есть `Dockerfile`, который описывает запуск проект и `docker-compose.yml` - запуск сервиса вместе с PostgreSQL.

### Запуск
```bash
docker compose up --build
```

Поднимаются два контейнера:
- `postgres` — PostgreSQL 16
- `transfer-service` — сам API-сервис, доступен на `http://localhost:5206`.

Миграции применяются автоматически при старте сервиса
